PhishGuard V2 Architecture & Methodology

About PhishGuard V2

An advanced, multi-layer, evidence-based phishing detection platform combining offline lexical heuristics, real-world threat intelligence feeds, domain telemetry, and ensemble machine learning.

1. Five-Layer Detection Engine Architecture

PhishGuard V2 replaces monolithic single-model scoring with a defense-in-depth, five-layer evidence aggregation architecture:

Layer A: Advanced URL Analysis

Leverages Public Suffix List (PSL) rules to extract true registered domains, decomposes subdomains, detects Punycode/homoglyphs, and flags brand-mimicking strings.

Layer B: Threat Intelligence

Connects to Google Safe Browsing, PhishTank, OpenPhish feeds, and local threat signatures. Implements TTL caching, timeout controls, and rate-limit fallbacks.

Layer C: Domain & TLS Signals

Safely checks DNS address resolution and TLS SNI certificate headers without downloading HTTP application content or following web redirects.

Layer D: Real-World ML & Registry

An ensemble Random Forest model validated through an artifact registry. Benchmarked against HistGradientBoosting, Decision Trees, and Logistic Regression.

Layer E: Evidence-Based Decision Engine

Aggregates threat intelligence, model probabilities, structural heuristics, and domain telemetry to produce one of four standardized verdicts: PHISHING DETECTED, SUSPICIOUS, NO KNOWN THREAT DETECTED, or INCONCLUSIVE.

2. Safe Server Architecture (Zero SSRF Risk)

PhishGuard enforces a strict architectural boundary: The application server never makes HTTP requests to user-submitted target URLs.

No HTML Crawling

Eliminates drive-by malware downloads, malicious JavaScript execution, and browser exploit payloads on the host server.

Zero SSRF Surface

Prevents Server-Side Request Forgery against cloud metadata APIs (e.g. 169.254.169.254), internal VPC services, and local loopbacks.

Millisecond Speed

Operates in sub-5 milliseconds for offline URL analysis without waiting for multi-second web page downloads.

3. Standardized Security Verdicts

Unlike naive detectors that output simple binary true/false flags, PhishGuard V2 maps multi-source evidence into four transparent security states:

  • PHISHING DETECTED: Confirmed match by active threat intelligence provider, or verified homoglyph/brand deception supported by high model probability.
  • SUSPICIOUS: Elevated risk observed (e.g. high-risk indicators, brand terms in subdomains, or elevated model score), but lacking confirmed threat intelligence match.
  • NO KNOWN THREAT DETECTED: Available threat intelligence feeds and lexical models find no threat indicators. Explicitly declared as NOT an absolute guarantee of safety.
  • INCONCLUSIVE: Evidence is insufficient, contradictory, or malformed. Returned when domain does not resolve or signals are inconclusive, avoiding false certainty.

4. Privacy Protection & Scan History

PhishGuard V2 includes built-in privacy safeguards:

  • Credential & Token Redaction: Embedded passwords, basic auth, and sensitive query tokens (e.g. token, auth, key, password) are scrubbed before storage.
  • Zero Third-Party Leaks: Scan history is stored locally in JSON format with strict retention limits and can be wiped instantly via the dashboard.
  • Hashed Threat Cache: External threat intelligence lookups use SHA-256 hashes for disk caching, preventing plaintext URL exposure.

5. Technology Stack

  • Backend: Python 3.11+, Flask Web Microframework
  • Machine Learning: scikit-learn (Random Forest, HistGradientBoosting, Decision Tree, Logistic Regression)
  • Data Processing: Pandas, NumPy, tldextract (Public Suffix List)
  • Threat Intelligence: Google Safe Browsing v4, PhishTank, OpenPhish, Local Signatures
  • Frontend & PWA: HTML5, CSS3, JavaScript, Bootstrap 5, Chart.js, Service Worker
  • Quality Assurance: pytest (45 automated unit & integration tests)
